# 社区文章写作规范

本文档沉淀了多轮社区文章写作和修改的经验，供后续写作时参考。目标不是约束创造力，而是避免反复踩同样的坑。

## 核心原则

**社区文章是判断，不是文档。** 读者来社区看的是观点和发现，不是方法论清单。文章应该回答"你发现了什么、你怎么判断的"，而不是"你做了什么步骤"。

**诚实比漂亮重要。** 负面的、不确定的、有条件限制的结论，比一个工整的"三句话总结"更有价值。读者能分辨什么是真正的判断，什么是修辞。

**第一人称不是问题，没有人称才是。** "我们"建立了作者和读者的关系。被动语态和"研究显示"制造距离感，在社区文章里是劣势。

## 文章结构

### 标题

- 标题应该包含判断，而不是只描述内容
- 好标题："把科创50拆了11,037遍：印钞机没找到，减震器留下了"
- 坏标题："科创50单标的择时研究总结"
- 标题可以长，但要让人想点进去看

### 开篇

- 前两段必须建立核心张力：初始假设 vs 最终发现
- 不要在开头罗列做了多少工作、跑了多少数据——读者先要知道"结论是什么"，再决定看不看细节
- 用一个具体的、可感知的对比来锚定主题（如"印钞机 vs 减震器"）

### 正文

- 按研究层的递进顺序展开，每层解决上一层留下的问题
- 每层开头说清楚这一层要回答什么，结尾说清楚回答了什么
- 表格和数字是证据，不是结论。表格后面必须跟一句"这意味着什么"
- 章节标题要有信息量，不要只写"第一轮结果""第二层分析"

### 结尾

- 不要对全文再做一次编号式总结（"最后的判断可以压缩成三句话"）
- 结尾回到开头的问题，给出一个更成熟的判断
- 可以有一句有力量的收束，但不要用对仗句强行升华

## 禁止的写法

### 过度使用"不是...而是..."对立结构

这个句式本身没问题，但一篇三千字的文章里出现十次就是问题。适当保留，大量删减。

### 段落结尾的过度总结

几乎每段结尾都来一句"这说明了..."、"这意味着..."、"因此..."，读起来像教科书。留一些结论让读者自己得出。

### 编号式总结

"第一...第二...第三..."、"三个具体的判断变化"、"可以压缩成三句话"——这是 AI 最典型的组织方式。把编号拆掉，让每个判断自然衔接。

### 表演性修辞

- "统计检验把漂亮故事拆穿了"——太戏剧化，应该平实地说"统计检验的结果"
- "通往未来 Alpha 的桥却塌了"——"桥塌了"用烂了，用精确描述替代
- "把实验规则钉死"——"钉死"是一种自以为有力的粗暴，社区文章不需要
- "最后的话"——太煽情，用"关键资料"或自然收束

### 方法论清单

社区文章不需要教读者怎么做研究。不要出现"可以复用到其他单标的研究的方法"这类 README 式清单。

### 对仗句收尾

"把它当成印钞机，证据远远不够；把它当成减震器，历史证据已经很强"——这句本身是好的，因为它有实质内容。但如果变成"既不是...也不是...而是..."这种纯粹修辞性的对仗，就删掉。

## 推荐的语言习惯

- 用"我们"建立对话感，用"你"拉近读者距离
- 具体细节胜过抽象概括：说"0.886元开盘，计入2bp滑点后首笔成交价0.8861772元"比说"精确复现了原研究起点"更有说服力
- 公开承认不确定性和错误（bug、数据坑、统计不过关），这比完美叙事更有可信度
- 短句。中文社区文章不是学术论文，15-25字一句，偶尔用更短的

## 数据使用

- 所有数字必须可追溯到源报告，不要在文章里凭空出现
- 同一条数字在文章不同位置出现时，保持一致
- 表格只放关键对比，不要为了完整放20行数据
- 关键数字在正文里再提一次，读者不一定看表格

## 审稿清单

写完或修改后，用这个清单自查：

1. 标题有没有判断，还是只描述了内容？
2. 前两段能不能让读者知道结论方向？
3. 有没有"三句话"、"第一第二第三"这类编号式总结？
4. "不是...而是..."出现了几次？超过3次就砍。
5. 有没有哪段结尾可以删掉而不影响理解？
6. 有没有方法论清单、README 式写法混进来？
7. 有没有表演性修辞（"拆穿"、"钉死"、"桥塌了"）？
8. 数字是否都能追溯到源报告？
9. 结尾是回到了开头的问题，还是在做机械总结？
